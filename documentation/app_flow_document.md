# StoreSync App Flow Document

## Onboarding and Sign-In/Sign-Up
A new user arrives at the StoreSync landing page by typing the URL or following a marketing link. The page features a clear prompt to sign up or sign in. To create an account, the user clicks “Sign Up” and is presented with options to register using an email address and password or to continue with a social login, such as Google or GitHub, handled by Clerk. In the email method, the user enters their name, organization name, email, and password. After submitting, they receive a confirmation email with a link to verify their address. Once verified, they are redirected to a welcome screen. If they choose social login, they grant permission to share basic profile information and, upon success, are immediately taken to the welcome screen.

From the sign-in screen, existing users can enter their email and password or choose a social login. If a user forgets their password, they click “Forgot Password” to open a page where they enter their registered email. They then receive a reset link by email. Following that link brings them to a secure form to enter and confirm a new password. After updating, they are taken to the sign-in page and can log in with the new credentials. Signing out is always available via a profile menu in the header, which logs the user out and returns them to the landing page.

## Main Dashboard or Home Page
After sign-in, the user lands on the main dashboard. At the top, a header displays the StoreSync logo on the left and the user’s name with a profile icon on the right. Below the header, a horizontal navigation bar provides links to Stores, Orders, Inventory, Analytics, Integrations, and Settings. On the left, a collapsible sidebar shows the same navigation options with icons for quick access. The main area of the dashboard shows overview widgets: total sales for the day, low-stock alerts, pending orders, and recent activity log entries.

Each widget can be clicked to navigate to a detailed view. For example, clicking the sales widget takes the user to the Analytics page, while the orders widget opens the Orders list. The stores module is highlighted by default on the sidebar, showing a table of connected stores with status indicators. A prominent button labeled “Add New Store” sits above the table, inviting the user to connect another sales channel. Above the dashboard, breadcrumbs indicate the current section and allow quick navigation back to the home view.

## Detailed Feature Flows and Page Transitions

### Adding and Managing Stores
When the user clicks “Add New Store,” a fullscreen form slides in, prompting them to choose a platform adapter such as Shopee or TikTok Shop. In the first step, they select the platform from a dropdown. On the next step, descriptive instructions appear explaining how to obtain API credentials or OAuth tokens. The user fills in the required fields—partner ID, secret key, or authorizes via OAuth—then clicks “Connect.” StoreSync validates the credentials by pinging the platform API. If successful, a confirmation page shows the store name, logo, and status as “Connected.” The user clicks “Finish” to return to the Stores list, where the new store appears with a green online badge.

### Order Management
Selecting the Orders link in the sidebar brings up a paginated table of all orders aggregated from all connected stores. Each row shows order ID, store source, customer name, order date, and status. The user can filter by date range or status through a filter panel opening from the top of the table. To view details, the user clicks on an order row. This navigates to an Order Detail page where line items, shipping address, payment method, and fulfillment steps are listed. Below the details, action buttons allow the user to mark the order as shipped, initiate a refund, or add notes. When the user marks an order as shipped, a modal appears to confirm shipping carrier and tracking number. After confirmation, the system updates the order status and sends a status update back to the original platform via the IntegrationService.

### Inventory Synchronization
From the sidebar, clicking Inventory shows a table of all products with current stock levels per platform. A search bar at the top lets the user search by SKU or product name. To adjust inventory manually, the user clicks on the stock quantity for a product, triggering an inline edit where they enter a new quantity and click “Save.” StoreSync then updates the database and enqueues a background job through Redis to push the change to all connected platforms. The user can also click a “Sync Now” button at the top right to force a full synchronization, with a progress modal showing each platform’s update status.

### Analytics and Reporting
Navigating to Analytics reveals a dashboard of charts and tables. The default view displays a sales timeline chart and a list of top-selling products. The user can change the date range by selecting preset options like Last 7 Days or custom dates from a calendar picker. Clicking on a chart segment drills into a detailed report page that lists orders and sales for that period. A “Download CSV” button at the top of each report allows exporting data. In addition, the user can switch between different report types—Revenue, Inventory Turnover, Customer Behavior—via tabs at the top of the analytics page.

### Integrations and Platform Adapters
Under the Integrations section, the user sees a list of all configured platform adapters, their connection status, and last sync time. Each adapter entry has an “Edit” button that opens a modal where the user can update API credentials or re-authorize OAuth. If the credentials fail, a warning icon appears next to the adapter, and clicking it shows a detailed error message explaining what went wrong and instructions to fix it. A “Remove” button in the modal allows unlinking a store and deleting its synced data after confirmation.

### Admin Panel for Team and Tenant Management
For organization administrators, a special Admin link appears in Settings. Clicking it takes the user to the Admin Panel where they can invite new team members by entering their email and assigning a role such as Admin, Manager, or Viewer. Invitations trigger an email with a sign-up link pre-associated with the organization. The panel also shows a list of active users, their roles, and last login time. Admins can change roles or revoke access at any time. Below the team section, there is an Organization Settings page where the admin can rename the organization or upload a logo that appears on PDF exports and reports.

## Settings and Account Management
The Settings section is accessible from both the sidebar and the profile menu in the header. On the Account Settings page, users can update their personal name, email address, and password. Changing the email triggers a verification workflow similar to sign-up. The Password section allows updating the password by entering the current password, then the new password twice. Below personal settings, Notification Preferences let the user toggle email alerts for events like new orders, low-stock warnings, or failed syncs. Changes are saved immediately when the user clicks “Save Preferences.”

If the user’s organization is on a paid plan, a Billing tab appears in Settings. This page shows the current subscription tier, next billing date, and a list of recent invoices with download links. To upgrade or change the plan, the user clicks “Change Plan,” selects a new tier from a modal, and enters payment details via an integrated Stripe form. After successful payment, the subscription updates and the billing page reflects the new plan.

After completing any settings change, the user clicks “Back to Dashboard” links in the breadcrumbs or the sidebar to return to the main flow.

## Error States and Alternate Paths
When the user inputs invalid data—such as a malformed API key or an incorrect email format—the form fields highlight in red and an inline error message explains the issue. For example, during store connection, if the platform API returns an authentication error, a banner appears above the form reading “Invalid credentials. Please check your partner ID and secret key.” Background tasks use retry logic, and if a Redis queue job fails repeatedly, the IntegrationService surfaces the failure in the Notifications menu with a link to view detailed logs.

If network connectivity is lost while browsing the dashboard or loading a report, a full-screen overlay says “You are offline” with a retry button that polls until the connection is restored. Any unsaved changes, such as inventory edits, remain in the form until the user reconnects and clicks “Save” again. Attempting to access a restricted area without proper role permissions redirects the user to an “Access Denied” page explaining they lack permission and providing a link back to the dashboard.

## Conclusion and Overall App Journey
A typical user journey begins with signing up via email or social login and verifying their account. They then connect one or more stores using platform adapters and return to the dashboard to see an overview of their multi-channel operations. From there, they navigate seamlessly to manage orders, adjust inventory, and review analytics. Administrators set up team members and configure organization settings while each user customizes their notification preferences. Throughout, error states are handled gracefully, guiding users to corrective actions without losing progress. Finally, billing and subscription management are integrated into the same interface, enabling users to scale their usage. Over time, StoreSync becomes the central hub for day-to-day e-commerce management, from adding new marketplaces to generating reports and ensuring inventory consistency across all channels.
